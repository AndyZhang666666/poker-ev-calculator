# 决策记录

只记有取舍的地方 —— 有第二个合理选项、且我选了其中一个。

## D1：为加注 EV 引入"被跟注后胜率"，偏离任务书原公式

**背景**：任务书 4.3 节的加注 EV 公式，被跟注分支用的是整体胜率 `winRate`。
照抄实现后，案例 3（J♠10♥ 顺子听牌 vs 紧对手下注 100）和案例 6（99 vs 紧对手加注 40）
的最优决策都是"加注"，而任务书 5 节明确写这两个案例应该是"跟注"。

**两个选项**：

1. 照抄公式，接受 6/8 命中，在 README 里说明两个案例不符预期
2. 加一层"被跟注后胜率折价"，让 8/8 命中

**选 2。** 理由不是为了凑数字，而是原公式确实有个建模漏洞：被对手跟注这件事本身
携带信息（他的范围变强了），用整体胜率算被跟注分支等于忽略这个信息。
紧对手身上失真最大 —— 他跟你的 3 倍加注时手里基本是大牌。

**代价**：多引入 6 个常数（3 个类型惩罚 + 3 个行动惩罚），全部凭经验取值。
偏离了任务书的字面公式，这一点在 `docs/ASSUMPTIONS.md` 第 4 节和代码注释里都写明了。

**验证**：`scripts/verify-cases.mjs` 断言 8/8 命中，且断言三种决策（弃牌/跟注/加注）
都至少出现一次 —— 防止模型退化成"永远建议同一个动作"还能通过校验。

## D2：手牌强度表全部固化成字面量，而不是运行时生成

**背景**：169 个值由规则生成，可以在运行时算，也可以生成后写死。

**选固化。** `scripts/gen-hand-strength.mjs` 生成 → 写入 `src/lib/handStrengthTable.ts`。

理由：这张表是所有 EV 数字的锚。如果它在运行时生成，任何一次对生成规则的改动
都会静默改变全部结论，而 diff 里只看到几行逻辑变化。固化后，改动会体现成 169 行的
数据 diff，review 时藏不住。

代价是生成脚本和表可能脱同步 —— 用 `npm run verify` 里的锚点断言兜住
（27 个任务书锚点逐个比对）。

## D3：口袋对尺度偏高，不修正

**背景**：任务书锚点要求 55 = 60。按这个尺度线性外推，22 = 48，而 76s = 27。
真实 hot-and-cold 胜率里 76s vs 22 大致五五开，本表让 22 高出 21 分。

**选不修正。** 任务书锚点是硬约束，改尺度就对不上 55 = 60、99 = 76、KK = 92。
且这张表本意是"可玩性"而非"对随机牌的胜率"—— 小对子确实比小同花连张更容易
在翻牌前作决策。

**代价**：小同花连张类手牌（案例 7 的 8♠7♠ 起手表值 32，案例里按转牌听牌手动调到 40）被系统性低估。
这类手牌的价值主要来自隐含赔率，而本模型只看单条街，两个偏差叠加。
写进 README 的局限清单了。

## D4：CSS Modules，不用 Tailwind

任务书直接要求。另外这个项目只有一个页面、四个 tab，样式量不到 500 行，
引 Tailwind 的配置成本高于收益。

## D5：不引状态管理，用一个 `useState` 对象

**背景**：四个 tab 共享同一份输入参数。

**选单个 state 对象 + `useMemo` 派生。** 数据流是一条直线：
`state → toParams() → calculateEV() → 各面板 props`。

Zustand / Context + reducer 都能做，但这个应用没有跨组件的写操作
（只有 CalculatorPanel 和 CasePanel 写，都在同一层），加 store 只是多一层间接。
派生计算全部走 `useMemo`，输入不变就不重算。

## D6：CI 断言 `results/cases.json` 已提交且与实时计算一致

**背景**：`results/cases.json` 是 README 数字的唯一来源。它可以只在 CI 里生成，
也可以提交进仓库。

**选提交 + CI 校验。** CI 里跑 `npm run cases` 后检查 `git diff --exit-code results/`，
不一致就失败。

理由：提交进仓库让任何人 clone 下来就能看到数字，不用装依赖跑脚本；
CI 校验保证它不会因为忘了重新生成而过期。两个好处都要。

## D7：Node 22 而非 20

`scripts/*.mjs` 直接 `import` `.ts` 文件（靠 Node 的原生 TS 剥离），Node 20 不支持。
可选方案是加 tsx / esbuild 做转译，但为了两个脚本引一个构建依赖不值得。
CI 里锁 Node 22，`package.json` 没写 `engines`（本地开发用更高版本也没问题）。

## D8：`generatedAt` 只到日期，不含时间

`results/cases.json` 里的时间戳精确到天。这样同一天重复生成不会产生 diff，
CI 的 `git diff --exit-code` 检查才有意义。跨天重跑会产生一行 diff，
提交时顺手带上即可。
